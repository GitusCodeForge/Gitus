* operation mode


| mode        | namespace                | visibility                                      |
|-------------+--------------------------+-------------------------------------------------|
| browse-only | config ~enableNamespace~ | config ~ignoreNamespace~ and ~ignoreRepository~ |
| host        | config ~enableNamespace~ | special repo                                    |

| mode        | allow push | repo-level perm. | branch-level perm. | webui acl config |
|-------------+------------+------------------+--------------------+------------------|
| browse-only | no         | no               | no                 | no               |
| host        | yes        | yes              | planned*           | no               |
| forge       | yes        | yes              | planned*           | yes              |

*: currently not implemented but there are plans to implement it

| mode        | user management | user management webui | description                |
|-------------+-----------------+-----------------------+----------------------------|
| browse-only | not applicable  | not applicable        | "read-only" for everyone   |
| host        | special repo    | no                    | for solodev or small teams |
| forge       | db              | yes                   | for nearly any usage       |

** browse-only mode

setting a gitus instance to be in browse-only mode will completely remove all the functionalities that isn't built-in to git; this includes things like issue tracking and signature verification. in browse-only mode, gitus is basically like git instaweb.

** host mode

users, namespaces and repositories are described by two specially designated
repositories instead of the database; see [[./host-mode.org]].

** forge mode

the full-featured mode. users, namespaces and repositories live in the
database, and the access control list is editable from the web interface; see
[[./visibility.org]] and [[./acl.org]].
